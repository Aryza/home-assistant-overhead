# Overhead Implementation Plan

> **For agentic workers:** Execute inline using superpowers:executing-plans. Steps use checkboxes.

**Goal:** Port all four Overhead views and their shared tracking and optional artwork functionality to Home Assistant.

**Architecture:** Reuse upstream pure Python and browser rendering through explicit host adapters. A Home Assistant coordinator owns polling and persistent card profiles, while authenticated WebSocket commands deliver snapshots and administer artwork.

**Tech Stack:** Python, Home Assistant config entries/coordinator, Pillow, JavaScript custom elements.

**Spec:** ../../design.md.

## Global Constraints

- Raspberry Pi deployment; Home Assistant dashboard; no Tesserae dependency.
- Preserve source attribution, AGPL-3.0, font licenses and all four views.
- Public feeds every sixty seconds, receivers every thirty seconds; executor-based blocking work.
- AI off initially; credentials server-side; previews do not submit paid jobs.
- Full source, installation ZIP, examples and honest verification report.

## Review Focus

- Concurrent preview/dashboard requests must not duplicate paid work or advance history.
- A restart during an uncertain paid request must not resubmit it.
- Offline feeds and missing photos must produce visible fallback states.
- Multiple entries/card profiles must not leak configuration or share mutable render state.
- Dashboard resize, reconnect and asynchronous render completion must not leave stale content or timers.

### Task 1: Host-independent tracking and history

Files: `custom_components/overhead/{engine,history,validation}.py`, `vendor/`, `tests/test_tracking.py`.

Interface: `Engine(folder, settings)`, `poll()`, `snapshot(profile, options, preview=False)`; history stores closest-approach rows and stable scheduled windows. Settings fix location/source; card options select presentation.

- [x] Write tests for filtering, feed fallback, closest approach, repeat previews, restart windows, separate profiles and coordinate validation; run to verify missing implementation.
- [x] Vendor upstream source and patch host seams; implement persistent engine/history and validated profiles with bounded caches and workers.
- [x] Run tracking tests and record result.

### Task 2: Artwork and catalogue

Files: `artwork.py`, `fal.py`, `tests/test_artwork.py`.

Interface: `Artwork.open(ctx, settings, subject=...)` implements upstream session API; `status()` and `action()` support management. fal adapter implements upstream `generate(model, prompt, refs, aspect, retries)`.

- [x] Write tests for preview holds, explicit generation, concurrent deduplication, atomic daily reservation, interrupted submissions, version restore and deletion.
- [x] Implement persistent queue/ledger, bounded workers, fal HTTPS adapter, retained versions, cut-outs, catalogue stats and cache cleanup.
- [x] Run tests without live paid API calls.

### Task 3: Home Assistant lifecycle and authenticated API

Interface: domain `overhead`; WebSocket `overhead/entries`, `overhead/snapshot`, `overhead/manage`, `overhead/metadata`.

- [x] Write tests for setup/config defaults, administrator restrictions, entry isolation and unload cleanup.
- [x] Implement config/options flow, static frontend registration, coordinator, small sensors and executor API handlers.

### Task 4: Dashboard card and management
